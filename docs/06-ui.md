# 06 — UI

The UI is split across two Unity UI technologies, plus a lot of small "card + scroll list" components.
All UI is **client-side rendering over networked state** — panels read from `ClientDataCache` (via the
sync layer, [05](05-data-sync-and-kpi.md)) or directly from manager events/`NetworkVariable`s, and they
mutate state only by calling the managers' public request methods.

```
        ┌── UI-Toolkit HUD (GameHUDController) ── timer, inspection/management dropdowns,
        │                                          bus-stop & fleet panels
 Player ┤
        │   uGUI panel system (UIManager + BasePanel) ── role dashboards, request panels,
        └                                                 report screens, role-gated buttons
```

---

## uGUI panel system

### UIManager + BasePanel

[`UIManager`](../Assets/Scripts/UI/UIManager.cs) is a singleton that owns a **stack** of open
[`BasePanel`](../Assets/Scripts/UI/BasePanel.cs)s:

- `BasePanel` wraps a `CanvasGroup` (show/hide via alpha + interactable + raycast, never deactivating the
  GameObject so it keeps receiving events). Each panel can declare a toggle `InputActionReference`, a
  close button, and an `isExclusive` flag.
- `UIManager.RequestToggle/OpenPanel/ClosePanel/CloseTopPanel` enforce LIFO behaviour (Escape closes the
  top panel) and "exclusive" semantics (opening an exclusive panel closes other exclusive ones). Panels
  never show/hide themselves directly — they ask the manager, so the stack stays consistent.

### Role-gated buttons

[`RequestButtonAccess`](../Assets/Scripts/UI/RequestButtonAccess.cs) lives on a persistent object and,
on `RoleManager.OnRolesUpdated`, shows/hides each toolbar button according to the local player's
`PlayerRole` (e.g. the Vendor & Finance buttons only for the Finance Manager, the HR button only for the
HR Manager). This is the main mechanism enforcing "you only see your role's tools."

[`RoleSelectionIMGUI`](../Assets/Scripts/UI/RoleSelectionIMGUI.cs) is the pre-game IMGUI role picker:
once connected and before a role is chosen, it draws buttons for each role (greying out taken ones) and
calls `RoleManager.SelectRole`.

## UI-Toolkit HUD

[`GameHUDController`](../Assets/Scripts/UI/GameHUDController.cs) drives a `UIDocument` (UXML/USS) — the
always-on heads-up display. It wires:

- The **clock**: date/time labels + Pause/1×/3×/10× speed buttons (→ `SimulationTimeManager.RequestTimeMultiplierRpc`).
- **Inspection** dropdown: toggles route/fleet visualizers ([07](07-visual-editor-tools.md)).
- **Management** dropdown: bus-stop placement tools.
- The **bus-stops panel** (sortable waiting/boarded passenger lists) and a live **fleet panel** refreshed
  by a coroutine.

There are also older HUD controllers ([`HUDController`](../Assets/Scripts/UI/HUDController.cs),
[`GameHUDController`]) — `GameHUDController` is the current UI-Toolkit one.

subscribe to the relevant `ClientDataCache` event (or manager event) on enable, register data interest,
and rebuild their card lists on update.

### The card / scroll-list pattern

Long lists use a reusable generic base, [`BaseScrollManager<T>`](../Assets/Scripts/UI/BaseScrollManager.cs),
specialized per data type (`BusScrollManager : BaseScrollManager<BusData>`,
`InventoryScrollManager : BaseScrollManager<InventoryItemData>`, plus bespoke
`MechanicScrollManager`/`WorkItemScrollManager`/`RouteScrollManager`). Each manages a pool of "card"
prefab instances (`*CardDisplay` / `*Card`) bound to one element. Drag handlers (`*DragHandler`) and
`ScrollRectNoDrag` support reordering (e.g. the maintenance priority queue, route stop order) without the
scroll view stealing the drag.

### Shared UI widgets

- [`AnimatedButton`](../Assets/Scripts/UI/AnimatedButton.cs) / [`AnimatedToggleButton`](../Assets/Scripts/UI/AnimatedToggleButton.cs)
  — DOTween-based hover/press/toggle button feedback (implement the pointer handler interfaces).
- [`SliderValueToText`](../Assets/Scripts/UI/SliderValueToText.cs) — binds a slider to a label.
- [`ScrollRectNoDrag`](../Assets/Scripts/UI/ScrollRectNoDrag.cs) — a `ScrollRect` that ignores drags so
  child drag-handlers work.
- [`UIRaycastDebugger`](../Assets/Scripts/UI/UIRaycastDebugger.cs) — logs what UI element is under the
  cursor (debugging click-blocking issues).

## Adding a panel

1. Create the panel object with a `CanvasGroup`, add `BasePanel`, set its toggle action / close button /
   exclusivity.
2. In your controller's `OnEnable`, `RegisterInterest` for the data you need and subscribe to the
   `ClientDataCache` (or manager) events; unsubscribe + `UnregisterInterest` in `OnDisable`.
3. If it's role-specific, wire its toolbar button into `RequestButtonAccess`.
4. Mutate state only by calling manager request methods — never write authoritative state from the UI.
