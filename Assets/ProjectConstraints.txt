Multiplayer Simulation Game.
One server (host player) for Simulation.
Encapsulation and seperation of concerns is critical between modules.
Design of the data is critical to support efficient multiplayer synchronization.

Road Network is static.
Bus Stops on the Road Network is static.
Routes are not static, they can be edited in-game by the player.
Routes are persistent, the high-level info is stored in a json.

Transport Manager manages the routes.
Routes are defined by an ordered list of bus stops.
In order for busses to navigate on routes, bus stop level information is not enough; they need road segment level path information.
Road segment level path information is also owned by the Transport Manager.
Transport manager calculates the path information and caches them.
Bus, etc asks transport manager for exact path information, if not cached Transport manager calculates it and adds it to the cache.
Transport manager uses RoutePathFinder class to calculate paths.

SimulationTimeManager singleton runs an abstract clock.
SimulationTimeManager broadcasts OnMinuteChanged, OnHourChanged, and OnDayChanged events. Other scripts can subscribe to the appropriate granularity instead of checking related stuff with update().

FleetManager is the database for the list of busses, their assigned schedules.
Fleet data is persistent, saved to a json.
Fleet manager only handles data.

DepotController is the bus spawner, it uses fleet manager data and spawns/despawns busses appropriately. (spawns directly at the first stop of the route, for now)
DepotController listens to OnMinuteChanged and checks schedules each time.

BusDriver manages a single bus.
BusDriver requests the path from TransportManager, and physically moves along the path.
When arrived at an intermediate stop, it waits for a set duration (constant for now)
When reaching a terminus, it waits for a turnaround time (different than intermediate stop wait time, set in the schedule)
If the route is not a ring, BusDriver traverses the route in reverse order. It requests new reverse paths from TransportManager.
When reached the first node of the route, it checks whether current time > operation end time (defined in schedule): if yes it returns to depot (despawns for now)
If current time <= operation end time, it starts a new trip along the route.
BusDriver only checks operation time at the first stop of the route, not at the last stop.
If the route is a ring (first stop == last stop), it does not traverse backwards.
